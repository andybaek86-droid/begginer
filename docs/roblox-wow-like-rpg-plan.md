# 로블록스 MMORPG형 육성 게임 기획서 (초안)

> 콘셉트: **WoW 스타일의 육성(레벨업·직업·장비·파티 던전) RPG를 로블록스에 맞게 가볍게 재해석**
> 상태: 초안 v0.1 — 아래 가정은 확정이 아니며 피드백으로 수정한다.

---

## 1. 콘셉트

| 항목 | 내용 |
|---|---|
| 한 줄 소개 | 직업을 고르고, 사냥·퀘스트로 성장해 파티 던전과 레이드 보스에 도전하는 로블록스 MMORPG |
| 타깃 | 10~16세 중심, 확장형으로 17세 이상 코어 유저 |
| 플랫폼 | PC(주력), 모바일(조작 단순화 필수), 콘솔(후순위) |
| 세션 길이 | 15~40분 (짧게 접속해도 성장이 체감되어야 함) |
| 차별점 | ① 로블록스 특성에 맞춘 쉬운 조작·짧은 루프 ② 파티/길드 중심 소셜 ③ 시즌제 서버 리셋 없이 지속되는 성장 |

### WoW에서 가져올 것 / 버릴 것
- **가져올 것:** 직업 정체성, 레벨업 쾌감, 장비 등급 수집, 파티 던전(탱·딜·힐), 길드, 필드 보스
- **버릴 것:** 복잡한 스킬 로테이션, 긴 이동 시간, 과도한 텍스트 퀘스트, 레벨 60+ 같은 긴 레벨 곡선
- **로블록스식 변형:** 스킬 4~6개로 제한, 자동 타겟팅 옵션, 빠른 이동 포털, 퀘스트 자동 진행 표시

## 2. 코어 루프

```
[사냥/퀘스트] → 경험치·골드·드랍 → [레벨업/장비 강화] → 더 강한 지역·던전 해금
      ↑                                                       │
      └─────────── 파티 던전 / 보스 레이드 ←──────────────────┘
```

- **분 단위 루프(1~3분):** 몬스터 처치 → 드랍 획득 → 스킬 사용 쾌감
- **세션 루프(15~40분):** 퀘스트 완료 → 레벨업 → 신규 스킬/지역 해금
- **일/주 루프:** 일일 퀘스트, 주간 레이드, 이벤트 보스 (재방문 동기)

## 3. 핵심 시스템

### 3.1 직업 (초기 4종)
| 직업 | 역할 | 특징 |
|---|---|---|
| 전사 | 탱커/근접 딜 | 높은 체력, 도발 |
| 마법사 | 원거리 딜 | 광역 스킬, 낮은 방어 |
| 사제 | 힐러 | 치유·버프, 파티 필수 |
| 도적 | 근접 딜 | 기동성, 크리티컬 |

- 직업당 스킬 6개(액티브 4 + 궁극기 1 + 패시브 1), 레벨/전직으로 확장
- 후속 업데이트로 직업 추가(= 신규 콘텐츠이자 수익 포인트)

### 3.2 성장
- 레벨 1~50(초기), 시즌 확장으로 상한 상향
- 스탯: 힘/지능/민첩/체력 단순화
- 장비 슬롯: 무기·방어구·장신구, 등급(일반 < 희귀 < 영웅 < 전설)
- 강화/옵션 재설정(골드 소모 → 골드 싱크)

### 3.3 콘텐츠
| 콘텐츠 | 인원 | 목적 |
|---|---|---|
| 필드 사냥 / 퀘스트 | 솔로~파티 | 기본 육성 |
| 던전 | 3~4인 | 장비 파밍, 파티 매칭 |
| 필드 보스 | 오픈 | 서버 단위 이벤트 |
| 레이드 | 8~12인 | 엔드 콘텐츠 |
| PvP 아레나 | 1v1~3v3 | 경쟁 (후순위) |

### 3.4 소셜
- 파티 자동 매칭, 길드(창설/길드 창고/길드 퀘스트), 거래(사기 방지 로직 필수), 채팅

## 4. 수익화 설계

원칙: **Pay-to-win을 피하고 편의·외형·성장 가속 중심**으로 설계한다. (유저 반발과 신고 리스크가 크다.)

| 상품 | 유형 | 예시 |
|---|---|---|
| VIP 패스 | 게임패스 | 경험치 +25%, 전용 칭호, 인벤토리 확장 |
| 2배 경험치/드랍 | 개발자 상품 | 30~60분 부스트 (반복 구매) |
| 외형(코스튬/펫/탈것) | 게임패스·상품 | 스탯 없음, 수집 욕구 자극 |
| 인벤토리·창고 확장 | 개발자 상품 | 편의성 |
| 스킬/스탯 초기화 | 개발자 상품 | 빌드 실험 |
| 시즌 패스 | 구독/패스 | 시즌 보상 트랙 |
| 프리미엄 페이아웃 | 플랫폼 | 체류 시간 증가가 곧 수익 |
| 광고 | 플랫폼 | 보상형 광고(부활, 보너스 드랍) |

수익 구조 요약: 유저 결제 → Roblox 수수료 30% 공제 → 개발자 약 70% → DevEx 환전 (자세한 내용은 앞선 대화 참고, 환율·정책은 변동 가능).

## 5. 유저 확보·리텐션

- **초반 이탈 방지:** 첫 5분 안에 레벨업 2~3회, 첫 던전 체험, 튜토리얼 최소화
- **리텐션 장치:** 일일 접속 보상, 주간 레이드 리셋, 길드 활동 보상, 시즌 이벤트
- **바이럴:** 파티 초대 보상, 친구와 함께 플레이 시 경험치 보너스, 짧은 영상 친화적 연출(보스전)
- **업데이트 주기:** 2주 소규모 패치, 4~6주 콘텐츠 업데이트 (로블록스 상위작은 업데이트 빈도가 높다)
- **썸네일/아이콘/제목:** 발견성에 직결되므로 출시 전 A/B 테스트

## 6. 기술 구성 (참고)

- 언어: **Luau** (Roblox Studio), 형상관리는 **Rojo**로 Git 연동 권장
- 서버 권한 설계: 데미지·드랍·거래는 **서버 검증** 필수 (익스플로이트 방어)
- 데이터: DataStore(레벨, 인벤토리, 길드), 저장 실패 대비 재시도·세션 락
- 성능: 모바일 대응(파트 수 제한, 스트리밍 활성화, 이펙트 경량화)
- 모듈 구조(안): `PlayerData`, `Combat`, `Skills`, `Inventory`, `Quest`, `Party`, `Dungeon`, `Shop`

## 7. 개발 로드맵

| 단계 | 기간(추정) | 산출물 |
|---|---|---|
| 0. 프리프로덕션 | 2~3주 | 기획 확정, 아트 방향, 프로토타입 범위 |
| 1. 프로토타입 | 4~6주 | 직업 1종, 사냥터 1곳, 레벨업, 기본 전투 |
| 2. 알파 | 6~8주 | 직업 4종, 퀘스트, 던전 1개, 인벤토리/상점, 저장 |
| 3. 비공개 테스트 | 3~4주 | 소규모 유저 테스트, 밸런스·이탈 구간 분석 |
| 4. 출시(소프트 런치) | - | 수익화 최소 구성, 모니터링 체계 |
| 5. 라이브 | 지속 | 업데이트·이벤트·직업/레이드 확장 |

> 1인 개발이면 위 기간의 2~3배로 잡고, **직업 1~2종 + 던전 1개**로 출시 범위를 줄이는 것을 권장한다.

## 8. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 콘텐츠 소모 속도 > 제작 속도 | 레벨 곡선 완만화, 반복 가능한 던전/랜덤 옵션, 시즌제 |
| 모바일 조작 난이도 | 자동 공격/자동 타겟, 버튼 UI 최소화 |
| 익스플로이트·복제 | 서버 권한 설계, 거래 제한/로그, 비정상 수치 탐지 |
| 초기 접속자 부족(매칭 불가) | 파티 매칭 없이도 가능한 솔로 던전, NPC 동료 |
| 과금 반발 | 스탯 판매 지양, 외형·편의 중심 |
| 로블록스 정책 | 아동 대상 콘텐츠·결제 유도 가이드라인 준수, 거래/도박 요소 금지 |
